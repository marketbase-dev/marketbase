MarketBase is a schema and a toolkit, not a platform. It runs on your Postgres, with your API keys, under your control. Nothing routes through us, because there is no us to route through.

You know this one

You run message v1 on audience v1. Then message v2 on audience v1. Then message v3 on audience v1.1. Somewhere past that point it stops being possible to say what ran on whom.

Six months later the questions arrive and none of them have answers. What were the search filters for this list? Did it come from Apollo, or Storeleads, or Sumble, and when? Is it still fresh? Where is the prompt that filled in that column? Did we already pay to enrich these people for another client?

The answers existed. They were in a Clay table, an n8n run, a CSV in someone's Drive, and a spreadsheet called final_v3_USE_THIS. None of those places was built to remember, so nothing did.

What MarketBase does about it

Never enrich twice

Every paid API response is cached before it is parsed, keyed on the call and its params. Re-runs, new pipelines, other clients, and bug fixes all read from cache. You see exactly what you spent and on what.

Somewhere to put everything else

Your CRM only wants clean records, so everything else ends up in CSVs, docs and links. Keep it here instead: raw pulls, half-qualified lists, research, transcripts. Promote to the CRM only what is real.

Every list knows where it came from

Source, filters, export date, and the prompt that produced each field, stored with the rows. So "where did this come from" is a query, not an archaeology project.

Change one thing without redoing everything

ICP rules, filters, prompts and audiences are versioned alongside the results they produced. Tweak a rule and you get a new version, not a rebuild from scratch.

Campaign status in one place

Who was messaged, from which tool, at which step, and what came back. Held together across every sending tool instead of scattered between them.

One store, every client

Run an instance per client, all on the same schema and tools. Competitor research and battle cards are built once and reused, instead of redone per engagement.

Context, not just records

Storing rows is easy. MarketBase also stores how each lead got here and why you decided what you decided, which is what makes the context worth sharing. Four concerns, kept separate.

ConcernWhere it livesThe question it answers
Provenancelead_sourcesHow did this lead get here?
Judgmentlead_qualificationsWhy did we target them, under which version of the rules?
Statelead_tagsWhat is true about them right now?
Outcomecampaign_membersWhat did we do, and what happened?

Because judgment is versioned and stored with its full result, you can re-run last quarter's qualifier and reproduce exactly why a lead was included. Because provenance is separate from judgment, you can change your targeting rules without losing the record of where anyone came from.

MarketBase does not send anything. It does not own your sequencer, and it will not try to replace your CRM. It owns the record of who you targeted and why.

Never pay twice

Every raw vendor response is cached before it is parsed, keyed on the API, endpoint, and normalized params. A job that dies on page 12 resumes from cache for pages 1 through 11.

Deal-aware suppression

Deal state syncs from your CRM, so leads at accounts with an open opportunity are held back automatically instead of getting cold outbound from a rep who did not know.

Quickstart

Requires Postgres 14 or newer. Any Postgres works: local, Neon, Supabase, RDS.

# Clone and point at a database
git clone https://github.com/marketbase-dev/marketbase.git
cd marketbase
export MARKETBASE_URL="postgresql://user:pass@localhost:5432/marketbase"

# Apply the schema (additive, safe to re-run)
psql "$MARKETBASE_URL" -f schema/000_bootstrap.sql
for f in schema/0*.sql; do psql "$MARKETBASE_URL" -f "$f"; done

Start from a CSV, not a database

Most people start with a spreadsheet. That path is first-class: point MarketBase at a CSV and get back a deduplicated list with provenance attached and suppression already applied.

marketbase import leads.csv --source apollo --label "Q3 ICP pull"
marketbase qualify --qualifier icp_v1
marketbase export --campaign q3_outbound --format csv

You do not need to know what a data warehouse is to use MarketBase. Postgres is an implementation detail.

Open datasets

MarketBase publishes open, well-structured GTM datasets under the same schema, so they load straight into your instance.

Every dataset ships with a manifest recording where it came from, when it was collected, its license, and its known limitations. Provenance is the whole point of this project, and that applies to our own data too.

Drive it from Claude Code

The repository is also a Claude Code plugin, so you can run the whole pipeline conversationally.

/plugin marketplace add marketbase-dev/marketbase
/plugin install marketbase@marketbase
CommandWhat it does
/marketbase:initProvision a database and apply the schema
/marketbase:sourceIngest leads from a vendor or CSV, recording provenance
/marketbase:qualifyRun a versioned qualifier over a cohort
/marketbase:stageStage qualified leads into a campaign
